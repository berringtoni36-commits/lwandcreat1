# 新增实验与方法的约定

## 先说明位置

- 修改固定项数基线时，标清与 v10 的差别，保留原始 v10 结果；不要把旧数据改名为新方法结果。
- 在动态项数原型上开发时，沿用 v11 的独立时间戳运行目录。新增机制要有独立开关或明确的新版本入口，便于与现有 v11 比较。
- 当方法、评估协议或代码结构变化较大时，新建 `experiments_<主题或版本>/`，其中至少包含 `README.md`、运行入口、核心实现、必要的正确性检查及 `outputs/`。不要让新目录直接修改旧目录的结果文件。

## 每轮运行需要留下什么

1. **问题与改动**：本轮只改了什么机制，预期观察什么指标。
2. **对照与工况**：固定 R=1/2/4/8、完整 RFF-MCC 等适用基线，以及输入、噪声、通道和样本长度。
3. **复现信息**：命令、参数、随机种子、Python/依赖版本、源码提交号或源码快照；对于混沌输入等，还需保存实际输入和初始化。
4. **逐次结果**：每次运行的原始曲线、指标、结构事件与错误检查，不只保存平均图。
5. **成本口径**：区分主体、候选训练/筛选/验证/切换、实测时间、活动参数与驻留参数；明确哪些运算未计入。
6. **结论范围**：开发试验与独立验证分开记录。固定结构更新的性质不能直接扩展成结构切换或真实 ANC 闭环的稳定性保证。

推荐为每轮结果建立 `outputs/<时间戳>_<smoke|pilot|validation>/`，其中放 `protocol.json`、原始数据、`summary.csv`、`REPORT.md` 和本轮源码快照。把运行结果加到所属实验的结果索引，并在 README 中写明哪些结果可用于论文。
