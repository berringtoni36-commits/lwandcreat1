# E2/E3 开发输入上的固定项数特征预算诊断

仅重用 `outputs/main_dev_round1` 已保存的 E2/E3 run00 开发输入，未接触 select/confirm。每例 400000 点，四段各 100000 点；每段末 5000 点 ANR 取均值。固定 R2/R3 使用原默认步长（E2 `mu=0.2`、E3 `mu=0.1`，两个因子各用一半），与原固定 R4、500 维的保存结果对照。结果是容量可行性诊断，不是在线特征预算选择器。

## 设计与成本

|特征数 D|Kronecker 形状 D1×D2|R2 完整乘法/点|R3 完整乘法/点|R2/R3 相对 R4 成本|
|---:|---:|---:|---:|---:|
|180|15×12|5778|6411|0.302 / 0.335|
|256|16×16|8172|9052|0.427 / 0.473|
|320|20×16|10180|11264|0.532 / 0.589|
|400|20×20|12692|14032|0.663 / 0.733|
|500|25×20|15822|17477|0.827 / 0.913|

原固定 R4、500 维完整成本为 **19132 次乘法/点**。各行按 `D×(M+1+Ls) + R×[3D+D2+3(D1+D2)] + 8 + Ls` 计，`M=20`、实际次级 FIR 长度 `Ls=4`；包含特征投影及缩放、filtered-x、顺序 MCC 的因子预测和更新，以及控制输出 FIR。重放脚本为配对方便逐点先算 500 维再取前缀；表中成本是假设单独部署该 D 维固定控制器、只投影 D 项时的完整理论乘法数，不是脚本实测耗时。若并行训练多条预算分支并在线挑选，还须加其他分支与选择成本。R4 的 90% 门槛为 17218.8 次/点。

各预算都取原 500 维 `Om/ph` 的前 D 项，按 `sqrt(2/D)` 计算 RFF，等价于将原 500 维的前缀乘 `sqrt(500/D)`；因子取同一保存初值的 A 前 D1 行、B 前 D2 行与前 R 列，不另作缩放。形状选用接近原 25:20 比例的较均衡因子；256 与 400 在本次采用方形，并非这些预算唯一的分解。D2 改变会改变 `reshape` 时的特征到矩阵位置映射，所以结果同时受到特征数、形状和重排影响，不能归因于单一特征数。RFF 前缀避免为小预算另抽有利的随机特征；共同的因子数值前缀也不保证各维度初始预测完全相等。

## 复现与校验

在仓库根目录运行：

```powershell
& 'C:\Users\nxtrol\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B experiments_v12/diagnostics/feature_budget/run_budget.py
```

脚本只读取 `main_dev_round1` 的 E2/E3 run00 NPZ、对应 summary/protocol，以及该轮保存的 v10 `anc_core.py`。原始输入的 SHA-256、逐段全部数值与完整成本保存在 `E2_run00.json`、`E3_run00.json`；`segment_results.csv` 每段一行，`config.json` 固定设计。500 维 R2 在同输入、同初值、同步长上与原保存四段 ANR 的最大差异为 E2 `2.73e-7` dB、E3 `2.96e-7` dB。两例补算约 89.3 和 92.3 秒；运行时仅用于复现记录，不等于控制器实时运算成本。
