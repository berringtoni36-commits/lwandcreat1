# N14 确认阶段骨架：当前锁定

本目录只含预备运行器、只读预检、单一主检验分析器与 **dev 短序列**测试。当前没有 `freeze_confirmation.json` 或 `freeze_confirmation_seal.json`，也没有生成、运行或分析任何 N14 `confirm` 随机数组。父任务必须先完成 E2/E3 各八次选择及 25 个配对组合分析、锁定唯一 `(μ_E2,μ_E3)` 和九种固定方法各工况的 μ，再审阅并冻结源码、协议和统计规则；未达到这些条件时，`--unlock-confirm` 仍不能派生确认随机流。

## 两级只读预检

[`check_confirmation.py`](check_confirmation.py) 可打印状态为 `draft_only` 的确认冻结文件/独立封签模板；它们带 `FILL_` 占位，不能解锁。正式 `--freeze … --select-freeze …` 预检先用选择阶段的冻结闸门核对选择源码、协议、开发审计及封签，然后**只读**核对选择输出的 16 份输入、固定和五档动态轨迹 SHA、800 次评价与 25 个配对联合事件，重新计算并比对 `selection_analysis.json`；若选择失败、不完整或选中项不唯一，立即停止。

确认冻结文件还须精确包含选择冻结/结果清单/分析 SHA、由该分析得出的 E2/E3 动态 μ 和九种固定方法各工况 μ、当前全部源码/协议 SHA、`n=20`、`K≥17`、单侧 `α₃=0.05/12`、`Pr(J_i=1)≤1/2`、E1/C1–C4 预定桥接 μ。单独的确认封签须绑定确认冻结 SHA 和选择分析 SHA，并记录父任务审阅决定。运行期间每阶段重复只读检查；来源或封签变化不能完成该运行。所有预检在任何 confirm seed 或输出目录之前进行；没有确认冻结文件的 `--check` 只报锁定。

## 正式运行的预定内容

唯一官方运行入口为 [`confirmation_runner.py`](confirmation_runner.py) 的 `--freeze … --select-freeze … --unlock-confirm --case E2 --run 0` 形式；现阶段不执行。各工况 run0–19 使用与 dev/select 分离的 `SeedSequence([20260928,14,3,case_id,run_id,component_id])`。E2/E3 仍是原四段物理非线性初级路径，E1 是三段同字典教师的迁移边界，C1–C4 是原静态物理桥接；全部调用 N14 生成器的相同 FIR、稳定噪声、logistic 和 RFF 公式。每一运行把真实输入、SeedSequence 键与逐数组 SHA 保存，再调用现有 45 分支固定核；只把**九个已锁定 μ 的固定方法**轨迹写出，未锁定的核内分支不保存、不参与确认分析。唯一周期动态候选调用原 `selector_resort.simulate`；E1 用预定 `.2` 作描述，C1–C4 用预定 `.2/.1` 并关闭经理，逐点对照原 v10 R4 核。

每个结果保存执行器输出、物理误差、ANR、全部自然候选/同 R 重排事件、逐点乘法分类、实际 rank、映射/输入/代码/冻结 SHA。按 `input → selected fixed → locked dynamic → result` 原子提交；同种子中断可复算并校验后恢复，损坏或与冻结版本不同的文件会停止而不覆盖。每一次正式尝试另写开始/结束记录、失败类型及耗时；算法或数值失败原样保留，**不会换种子替代**。输出路径拟为 `experiments_v14/outputs/n14_confirm_<freeze_sha前16位>/caseE2/E3/E1/C1..C4_run00..19/`。

## 唯一主检验与桥接

[`confirmation_analysis.py`](confirmation_analysis.py) 只有在 E2/E3 及 E1/C1–C4 各 20 次均已有运行尝试后才产生最终分析。某次尝试没有可信完整结果即记该工况失败；不会删除它或改变分母。20 对中每对单一 `J_i=1` 要求两工况均满足：四段动态对所锁固定 R4 的退化 ≤0.5 dB，双方各段 ANR ≤−6 dB；含全部 R2→R2 搜索的完整在线乘法 ≤R4 的 0.9；经物理验证真正 R4→R2 且在样本 80000 前完成执行器切换、之后保持 R2；物理 FIR、ANR 和成本账本重演通过。同 R 更新不算新的降项。计算 `K=ΣJ_i` 与一次单侧精确二项尾概率，**K≥17/20** 且 `p≤.05/12` 才通过，并以精确尾概率反解单侧成功率置信下界。只报一个预先固定的主检验，不从确认集再选 μ 或配置。

E1 的三段和 C1–C4 的固定前沿、动态描述及失败均附原值。C1–C4 关闭经理的每点输出/物理误差要与冻结 v10 R4 核相差 ≤1e−10；若桥接失败，即使主 `K` 达标也不允许整体实现完整性主张。绝对优势于 full500 或 Pareto 表述仍须另由确认固定前沿判断，不能由相对 R4 的主 `J_i` 推出。

测试命令是 `python experiments_v14/confirmation/test_confirmation.py`。它只使用 80 点左右的 **dev** E2/E1/C1 烟雾数组与合成统计字典，测试无冻结拒绝、输入/固定/动态断点恢复、四/三/单段适配、C1 原 v10 数值桥接、`K=17` 与 `K=16` 的精确概率及失败保留。测试文件写在系统临时目录并删除；它不会采样 `phase=confirm` 的 SeedSequence。
