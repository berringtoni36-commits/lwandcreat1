# N14 固定 RFF-Kronecker-MCC 前沿：仅开发集

**状态：已完成 N14 新 dev 输入的 E2/E3 各 5 条、每条 400000 点；未使用或生成 select/confirm。** 最后一份 `result.json` 于 **2026-09-28 08:59:09 UTC（北京时间 16:59:09）** 写成。十份计算在不超过四个工作进程下完成，每份核心计算及轨迹存盘 26.5–36.3 秒，逐份耗时见结果文件；十份耗时合计 345.20 秒，不能将此并行任务耗时合计解释为墙钟时长。

## 数值与公平设置

- 每个输入只从 [`n14_dev_inputs/manifest.json`](../outputs/n14_dev_inputs/manifest.json) 取 N14 **dev** E2/E3 run0–4，先核对整个 NPZ 的 SHA-256；同一运行的 45 个分支完全共用 `x,d,v,Ω,φ`，R1–R8 共用保存的八列 `A0,B0` 前缀，full500 从零系数开始。
- 固定 R1–R8 各扫 `μ=.05,.10,.20,.40,.80`（两个因子各用 `μ/2`），full500 同样扫五档 `μ`。每个分支独立执行器历史，次级物理 FIR `S=[0,0,1,.5]`；四段各 100000，逐段仅末 5000 点的原 ANR。45×4 个原值逐运行保存，**没有逐段挑 μ 的事后包络**。
- 固定成本包括 10000 RFF 投影、500 缩放、2000 filtered-x、4 物理输出 FIR，`C_R=12512+1655R`，full500 为 14508 次乘法/点。例如 R1=14167、R2=15822、R4=19132、R8=25752。R4 每 400000 点为 7,652,800,000 次，full500 为 5,803,200,000 次。成本只指审计口径的标量乘法，不等同墙钟或能耗。
- [短序列测试](test_frontier.py)把 45 条分支逐点对照冻结的 v10 核及物理输出，先 B 后 A 的 MCC 顺序一致。每份保存的执行器输出和误差另做 FIR 重演，十份均在 float32 轨迹存储舍入界内；[独立分析器](analyze_frontier.py)由保存误差重算四段 ANR，最大绝对差 **1.35×10⁻⁸ dB**。清单、输入、轨迹和结果 SHA 及可核对汇总在 [`summary.json`](summary.json)。

## 开发前沿的原值结论

以下是五条开发运行 × 四段的等权 ANR 均值，越负越好；**不是**未来选择集确定的公平步长。

| 方法 | E2 μ=.05 | E2 μ=.10 | E3 μ=.05 | E3 μ=.10 | 乘法/点 |
|---|---:|---:|---:|---:|---:|
| 固定 R2 | -7.007 | -6.832 | -6.368 | -6.231 | 15822 |
| 固定 R4 | -9.288 | -9.258 | -8.353 | -8.303 | 19132 |
| 固定 R8 | -11.056 | -11.141 | -9.976 | -10.039 | 25752 |
| full500 | -12.277 | -12.276 | -11.179 | -11.150 | 14508 |

在新流 **run0**，固定 R4 的 μ=.05 对 E2 四段为 `[-9.409,-9.218,-8.493,-10.091]` dB，μ=.10 为 `[-9.333,-9.053,-8.379,-9.966]`；E3 分别为 `[-9.247,-8.552,-7.291,-8.851]` 和 `[-9.061,-8.409,-7.239,-8.687]`。因而 run0 的四段均是 `.05` 较好，不能照搬旧 E2/E3 开发样本的步长趋势；其余 run 有交叉，完整均值在 [`summary.json`](summary.json)。五运行开发均值下，E2/E3 固定 R4 均以 `.05` 略优于 `.10`，差仅 0.030/0.050 dB。

full500 μ=.05 在 E2/E3 共 **40 个逐运行逐段比较**中全部优于固定 R4 μ=.05，单段优势范围 E2 为 2.100–3.804 dB、E3 为 2.221–3.273 dB；同时 full500 固定成本仅为 R4 的 **0.7583**，也低于 R2 的成本。这是对 N14 可能的**全固定前沿**表述的直接约束：即便动态方法将来通过相对固定 R4 的窄门槛，也不能仅据此声称优于 full500 或位于全方法 Pareto 前沿。当前数据本身尚未运行动态方法，不推断其未来确认表现。

## 将来选择集的复用边界

[`selection_interface.py`](selection_interface.py) 为正式固定方法规定唯一接口：每个工况收齐八份 **select** 阶段结果后，对每一种固定方法的五档 μ 分别计算 `8×4` ANR 等权均值，选最小者、平局取较小 μ，再将该方法**同一档 μ**用于全四段；E2 与 E3 各自锁定。接口拒绝 dev 标记、缺少运行或逐段选择。它没有生成选择流，也没有用本开发前沿锁定正式 μ。动态组合筛查另按 [N14 草案](../protocol/PREREGISTRATION.md) 的 25 个配对步长联合事件规则，不由此固定接口决定。

重现命令（路径相对项目根目录，使用已经安装 Numba 的 Python 环境）：

```text
python experiments_v14/fixed_frontier/test_frontier.py
python experiments_v14/fixed_frontier/run_frontier.py --case E2 --run 0
python experiments_v14/fixed_frontier/run_frontier.py --case E3 --run 0
# 同一命令分别替换 run=1..4；已有相同 SHA 结果时可恢复跳过。
python experiments_v14/fixed_frontier/analyze_frontier.py
```

`manifest.json` 冻结核心源码、协议、输入总清单、环境与成本哈希；每个 `caseE*_run*/result.json` 链接对应输入和 `traces.npz` 的 SHA。代码仅位于本 `fixed_frontier/`，原 v10–v13 算法与 N14 协议核心未因本固定前沿改动。
