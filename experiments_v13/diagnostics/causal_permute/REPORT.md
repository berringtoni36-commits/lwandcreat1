# E2/E3 开发运行：因果时点的 R4 排列压缩与在线续训

在已保存的原始密集 500 维 RFF 映射上，本诊断让固定 R4 从原嵌套初值连续在线运行。每段开始后 **20000** 或 **50000** 点这两个预定时点，仅凭该时刻、完成当前样本更新后的 R4 因子构成 500 维权重。预先指定四种排列：当前 R4 权重的跨网格带符号升序、第一段相同时点的排序固定迁移、恒等顺序、与数据无关的固定随机顺序（种子 `2026092814`）。每种都作相同的 `20×25` SVD 截断到 R2/R3，继承 R4 已产生的实际控制输出 FIR 历史与 ANR 平滑状态，从下一点起按归档 v10 顺序 MCC 独立更新到该段结束；末 5000 点物理 ANR 与持续运行的原 R4 比较。每段分支在段末丢弃，下一段仍由未中断的 R4 提供起点。

只使用 `experiments_v12/outputs/main_dev_round1` E2/E3 各 run00 开发输入与该轮归档 v10 核心；未读 select/confirm，未改 v10–v12。E2 步长 `mu=0.2`、E3 `mu=0.1`，A/B 因子各用 `mu/2`，与原固定 R4 一致。四段每段 100000 点，段界、切换时点和比较窗口均预先固定。**段界本身在真实在线任务中未必已知**；这个试验是允许已知段界与硬切换的独立上限诊断，没有实现候选训练、验证门控或平滑切换。

固定排列下首段之后的初始 Frobenius 截断误差会升高：例如 E2 20k 时点的 R2，从当前排序的 `0.062–0.094` 增至固定首段排序在后续段的 `0.532–0.600`。但之后的在线 MCC 续训仍使末窗 ANR 接近或优于 R4，提示这里的改善不只是对原 R4 权重作静态压缩；不同排列下的学习轨迹也改变了。该解释仍是开发数据上的机制线索，并无独立确认。

没有增加“当前排序但维持 R4 项数”的等价臂：恒等顺序下当前权重矩阵的数值秩为 4，跨网格带符号排序后在全部 16 个预定切换的数值秩均为 **20**。若要求排列后精确表示同一个 500 维权重，就需要最多 R20（该 v10 Kronecker 主体约 `45612` 次乘法/点）或改用完整 500 系数控制器；R4 因子无法做到仅重参数化而不损失输出。已在每次切换验证未截断向量在同步排列的实际 `z/q` 上输出不变，这给出了等价的静态输出核对，但不伪称存在同成本、同更新规则的排序 R4 在线分支。

## 排列、重构与历史校验

原 R4 系数构成 `W=B Aᵀ`，其原特征向量 `w=vec(W)`；对任一排序 `p`，在切换时验证 `z[p]·w[p]=z·w` 和 `q[p]·w[p]=q·w`。所有 **128** 次初始化的最大差为 `1.34e-15`。对排列后矩阵做最佳 Frobenius SVD 截断，验证 `‖Wₚ−BᵣAᵣᵀ‖F/‖Wₚ‖F` 等于舍弃奇异值能量计算，最大差 `4.45e-16`；截断因子在实际排列特征上的输出也与直接投影权重相符。每个 R2/R3 分支复制 R4 在切换时的四抽头实际输出缓冲，因此切换前次级 FIR 历史误差严格为零。**之后的分支输出可能突然变化**；本试验没有渐变或切换风险门控。完整排列索引和逐分支核对记录分别在 NPZ/JSON 中。

## 成本口径与缺项

单条原映射固定控制器的完整 v10 乘法账本包含 RFF 特征生成、filtered-x、顺序 MCC 更新与一次实际输出 FIR：R4 为 `19132`、R3 为 `17477`、R2 为 `15822` 次/点。重放脚本为了配对比较同时训练所有反事实分支；下表只表示假设预定时点立即停用 R4、继续**一条** R2/R3 分支时，每段的平均**主体**成本：

|时点|目标秩|平均主体乘法/点|相对连续 R4|加一次性约定 SVD 账本后/点|
|---:|---:|---:|---:|---:|
|20k|R2|16484|0.862|16494.021|
|20k|R3|17808|0.931|17818.021|
|50k|R2|17477|0.913|17487.021|
|50k|R3|18304.5|0.957|18314.521|

一次切换还至少需要构造 `W=B Aᵀ` 的 `500×4=2000` 次乘法，以及 SVD 因子缩放 `R×(25+20)` 次乘法；表最后一列将 v12 对库 SVD 的**约定** `1,000,000` 次乘法收费摊到 100000 点上。它不是 SVD 的精确硬件计数。四组 SVD 臂采用相同主体与 SVD 账本；恒等臂无需排序，固定随机臂的排列预先生成，而当前权重排序臂还需 500 项排序比较/搬移。除恒等臂外，每点 `z` 与 `q` 各有 500 次置换访存；一次 500 项排列存储（`uint16` 为 1000 字节）。这些访存、四抽头缓冲与平滑状态复制、输出切换、候选验证及可能的 R4/R2 并行驻留均未折入主体乘法。W 构造、排序与 SVD 的试运行壁钟时间逐切换保存在 JSON；该时间依赖 Python/BLAS，不作为实时保证。

尤其是**在线门控不能预先知道哪条分支会成功**。若切换后仍并行维持 R4 与 R2 以供因果验证，仅共享一次 12500 次/点的 RFF 生成和滤波，两条固定分支的基础账本就约 `22454` 次/点；R4 与 R3 为 `24109` 次/点，尚无筛选、拒绝、渐变或长期驻留成本。这说明上表低于 R4 的主体成本是一个允许直接硬切换、无验证分支的乐观边界，不能等同可部署在线节省。
